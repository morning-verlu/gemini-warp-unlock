> Fix **"Gemini isn't supported in your country/region"** — route Gemini / AI Studio /
> OpenAI / Claude traffic through a clean **Cloudflare WARP** egress, chained behind an
> **Xray VLESS + Reality** node, with a ready-to-import **Clash / mihomo subscription**
> generated by one command.

## Why

Cheap VPS IPs (especially datacenter IPv6 ranges) are often geolocated incorrectly or
have low reputation in Google's IP database, so logging into [gemini.google.com](https://gemini.google.com)
through them shows the region error even when the TCP connection works fine.
Splitting AI domains onto a dedicated **native WARP exit (US)** while sending everything
else direct (forced IPv4) fixes the region check without slowing down normal traffic.

```
Clash Verge / mihomo (client)
  └─ VLESS + Reality + Vision ──► VPS: Xray :443
                                    ├─ Gemini / AI Studio / OpenAI / Claude ──► warp-cli SOCKS5 :40000 ──► WARP US
                                    └─ all other traffic ─────────────────────► VPS direct (IPv4 forced)
```

**Scope / limitation:** this solves the **IP layer** only. If your Google account itself
is registered to a blocked region, a clean IP cannot save it — use a US-region account.
The [detailed guide](docs/GUIDE.zh-CN.md) (中文) explains the two-layer diagnosis.

## Features

- **One command, end to end** — installs `warp-cli`, patches Xray (WARP outbound +
  per-domain routing + IPv4-forced direct), generates the Clash subscription, sets up nginx
- **Staged execution** — `warp` / `xray` / `sub` / `nginx` / `verify` run independently for easy debugging
- **Idempotent & safe** — re-running adds no duplicate rules; the original Xray config is backed up automatically;
  the Reality public key is derived from your private key
- **Panel-free, minimal attack surface** — no web admin port; one readable JSON + one YAML, easy to version and migrate
- **Batteries-included subscription** — LAN direct, ad blocking, AI/streaming groups, CN direct rules, QUIC blocked, fallback to proxy

## Quick Start

Requires Debian 11/12/13 or Ubuntu 20.04+, running as root, with an existing working
Xray VLESS + Reality inbound.

```bash
curl -fsSL https://raw.githubusercontent.com/morning-verlu/gemini-warp-unlock/main/xray-warp-setup.sh -o setup.sh
chmod +x setup.sh && ./setup.sh

# Brand-new machine (xray binary installed, no config yet — UUID/Reality keys are auto-generated):
./setup.sh --init
```

The script prints the subscription URL:

```
http://<VPS_IP>:8888/my-sub/clash-<random>.yaml
```

Paste it into **Clash Verge Rev / Clash Verge X → Profiles**, refresh, and select it.

### Stages

```bash
./setup.sh warp     # install & configure WARP (proxy mode, SOCKS5 :40000)
./setup.sh xray     # patch Xray config and restart
./setup.sh sub      # regenerate the Clash subscription
./setup.sh nginx    # configure nginx subscription delivery
./setup.sh verify   # run final checks
```

### Environment Variables

| Variable | Default | Description |
|---|---|---|
| `NODE_DOMAIN` | auto-detected public IPv4 | VPS address / domain |
| `WARP_PORT` | `40000` | warp-cli SOCKS5 port |
| `XRAY_CONF` | `/usr/local/etc/xray/config.json` | Xray config path |
| `SUB_PORT` / `SUB_PATH` | `8888` / `/my-sub` | subscription port / path |
| `SUB_FILE` | `clash-<random>.yaml` | subscription file name |
| `PROXY_NAME` | `US-Reality-WARP` | node name inside the subscription |
| `FORCE_IPV4` | `1` | force IPv4 on the direct outbound |

## Verify

```bash
# On the VPS — WARP must be online:
curl -s --socks5-hostname 127.0.0.1:40000 https://www.cloudflare.com/cdn-cgi/trace | grep warp=
# expected: warp=on
```

Then open https://gemini.google.com in an **incognito window** on the client and sign in.
